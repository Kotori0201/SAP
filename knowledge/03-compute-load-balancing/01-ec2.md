# Amazon EC2 – Instance types, Placement Groups, Purchasing options

[⬅ Về mục lục section](README.md)

## 📖 Định nghĩa

| Thuật ngữ | Định nghĩa |
|---|---|
| **Amazon EC2 (Elastic Compute Cloud)** | Dịch vụ cung cấp **máy chủ ảo (instance)** có thể thay đổi kích thước, trả tiền theo thời gian sử dụng. |
| **Instance type** | Cấu hình phần cứng của instance (vCPU, RAM, mạng, lưu trữ), đặt tên theo *họ + thế hệ + kích thước*, vd `m7g.large`. |
| **Placement group** | Chiến lược điều khiển cách AWS **đặt các instance lên phần cứng vật lý** (gần nhau, rải rác, theo phân vùng). |
| **Purchasing option** | Hình thức mua/thanh toán instance: On-Demand, Spot, Reserved, Savings Plans, Dedicated. |
| **AWS Graviton** | Dòng chip **ARM** do AWS thiết kế, cho **giá/hiệu năng tốt nhất** trên EC2. |
| **Status check** | Kiểm tra tự động mỗi phút: **System status** (phần cứng/hạ tầng AWS) và **Instance status** (hệ điều hành/VM). |
| **Instance recovery** | Tự động chuyển instance sang phần cứng khác khi system status check lỗi, giữ nguyên cấu hình. |

## Nội dung chính

### Kiến trúc nhiều lớp trên AWS

> 📖 **Định nghĩa:** **Solution architecture** là cách ghép các dịch vụ thành từng lớp (DNS, CDN, web, compute, cache, DB, lưu trữ, decoupling) để đáp ứng yêu cầu của ứng dụng.

| Lớp | Dịch vụ |
|---|---|
| DNS | Route 53 |
| CDN | CloudFront |
| Web | CLB, ALB, NLB, API Gateway, Elastic IP |
| Compute | EC2, ASG, Lambda, ECS, Fargate, Batch, EMR |
| Cache / Session | ElastiCache, DAX, DynamoDB, RDS |
| Database | RDS, Aurora, DynamoDB, OpenSearch, S3, Redshift |
| Decoupling / Orchestration | SQS, SNS, Kinesis, Amazon MQ, Step Functions |
| Storage | EBS, EFS, Instance Store |
| Static assets | S3, Glacier |

### Các họ instance chính

> 📖 **Định nghĩa:** **Instance family** là nhóm instance tối ưu cho một loại workload (tính toán, bộ nhớ, lưu trữ, GPU…).

| Họ | Tối ưu cho | Ví dụ workload |
|---|---|---|
| **R** | RAM | In-memory cache, DB in-memory |
| **C** | CPU | Tính toán, batch, DB nặng CPU |
| **M** | Cân bằng ("medium") | Web app, ứng dụng chung |
| **I** | I/O local (instance store NVMe) | Database, NoSQL |
| **G / P** | GPU | Render video, ML training/inference |
| **T (T3/T4g)** | **Burstable** – có CPU credit | Workload thấp, thỉnh thoảng tăng; chế độ **unlimited** cho burst không giới hạn (tốn thêm phí) |

> 💡 Hậu tố: `g` = Graviton (ARM), `a` = AMD, `i` = Intel, `n` = mạng cao, `d` = có instance store.

### Placement Groups

> 📖 **Định nghĩa:** **Cluster** đặt instance sát nhau trong 1 AZ; **Spread** đặt mỗi instance trên phần cứng riêng; **Partition** chia instance thành các nhóm rack tách biệt.

| Chiến lược | Đặc điểm | Ưu | Nhược | Use case |
|---|---|---|---|---|
| **Cluster** | Cùng rack, **cùng AZ** | Mạng cực nhanh, độ trễ thấp (tới 10–100 Gbps với Enhanced Networking) | Rack hỏng → **tất cả** instance hỏng | Big Data job cần xong nhanh, HPC, ứng dụng cần low latency + throughput cao |
| **Spread** | Mỗi instance trên phần cứng khác nhau, **trải nhiều AZ** | Giảm rủi ro hỏng đồng thời | **Tối đa 7 instance/AZ/group** | Ứng dụng quan trọng, mỗi instance cần cô lập lỗi |
| **Partition** | Tối đa **7 partition/AZ**, mỗi partition dùng rack riêng; hàng trăm instance | Một partition hỏng không ảnh hưởng partition khác; instance đọc được **partition info qua metadata** | Một partition hỏng ảnh hưởng nhiều instance | **HDFS, HBase, Cassandra, Kafka** (ứng dụng phân tán có nhận biết topology) |

- Di chuyển instance vào/ra placement group: **stop** → CLI `modify-instance-placement` → **start**

### Purchasing options

> 📖 **Định nghĩa:** **On-Demand** trả theo giây, không cam kết; **Spot** dùng dung lượng dư của AWS giá rẻ nhưng có thể bị thu hồi; **Reserved Instance (RI)** cam kết 1–3 năm để được giảm giá; **Dedicated Instance/Host** là phần cứng riêng cho bạn.

| Loại | Đặc điểm | Dùng khi |
|---|---|---|
| **On-Demand** | Ổn định, giá cố định, đắt nhất | Workload ngắn, không đoán được |
| **Spot** | Giảm tới **90%**, **có thể bị thu hồi** (báo trước 2 phút) | Batch, phân tích dữ liệu, workload chịu được lỗi |
| **Reserved Instances** | Cam kết **≥ 1 năm** | Workload dài hạn, ổn định |
| **Convertible RI** | Đổi được loại instance | Dài hạn nhưng cần linh hoạt |
| **Savings Plans** | Cam kết **$/giờ** trong 1–3 năm (Compute SP linh hoạt cả Fargate, Lambda) | Thay thế RI hiện đại |
| **Dedicated Instance** | Không chia sẻ phần cứng với khách khác | Yêu cầu tuân thủ |
| **Dedicated Host** | Thuê **nguyên server vật lý**, kiểm soát vị trí instance, **host affinity** | **License tính theo core/socket** (BYOL Windows, Oracle, SQL Server) |
| **Capacity Reservations** | Giữ chỗ dung lượng ở 1 AZ, không giảm giá | Đảm bảo có capacity cho sự kiện/DR |

- Mức giảm RI: **All Upfront > Partial Upfront > No Upfront**

### EC2 Graviton

> 📖 **Định nghĩa:** Xem bảng định nghĩa ở trên.

- **Giá/hiệu năng tốt nhất**; Graviton2 tốt hơn ~40% so với x86 thế hệ 5; Graviton3 tới 3x Graviton2 (đã có Graviton4)
- Hỗ trợ nhiều Linux (Amazon Linux, RHEL, SUSE, Ubuntu); **không hỗ trợ Windows**
- Use case: app server, microservices, HPC, ML trên CPU, encode video, gaming, in-memory cache
- Cần build lại cho kiến trúc **ARM64** (image container multi-arch)

### Metric có sẵn của EC2

> 📖 **Định nghĩa:** **CloudWatch Agent** là phần mềm cài trên instance để gửi metric hệ điều hành (RAM, disk) và log lên CloudWatch.

- **CPU**: CPUUtilization, CPU credit usage/balance (instance T)
- **Network**: NetworkIn/Out
- **Status check**: instance status & system status
- **Disk**: read/write ops/bytes (chỉ **instance store**)
- ⚠️ **RAM KHÔNG có sẵn** → phải cài **CloudWatch Agent** (custom metric)

### EC2 Instance Recovery

> 📖 **Định nghĩa:** Xem bảng định nghĩa ở trên.

- CloudWatch Alarm theo dõi `StatusCheckFailed_System` → action **Recover** (+ SNS báo)
- Instance sau recovery **giữ nguyên**: private IP, public IP, Elastic IP, metadata, placement group
- Hiện nay nhiều instance có **simplified automatic recovery** mặc định

## 🎯 Mẹo thi

- "HPC / độ trễ mạng thấp nhất giữa các node" → **Cluster placement group** (+ EFA)
- "Cassandra/Kafka/HDFS cần cô lập lỗi theo rack" → **Partition**
- "Vài instance quan trọng phải nằm trên phần cứng khác nhau" → **Spread** (nhớ giới hạn 7/AZ)
- "License tính theo socket/core" → **Dedicated Host**
- "Theo dõi RAM" → **CloudWatch Agent**
- "Giữ nguyên IP khi phần cứng lỗi" → **EC2 instance recovery**
- "Giảm chi phí cho workload Linux phổ biến" → **Graviton**
